# Phase 8a — build list (BLFS 13.1-systemd closure)

Researched 2026-10-17. Research only: nothing was built or installed. "Verified" below means I read the package's own `meson.build` / `configure.ac` from the release tarball or the tagged source, not that I compiled it. BLFS pages: <https://www.linuxfromscratch.org/blfs/view/stable-systemd/>.

## Summary

**54 numbered packages**: 52 firm, plus 2 optional (#5 sshd unit files, #47 alsa-utils). Beyond those: 3 optional extras (libsndfile, Vulkan-Headers, Vulkan-Loader), 1 *conditional* package (Linux-PAM, see Open question 1), and 1 rebuild (FreeType, built twice). No Rust, no X11 and no PAM is needed by anything in the target list. The one real cost is **Intel Mesa**: both `iris` and `anv` need Mesa's `mesa_clc` build tool, which pulls in **LLVM + clang (shared) + SPIRV-LLVM-Translator + SPIRV-Tools + glslang** (verified in Mesa 26.1.7 `meson.build`: `with_clc` is forced on by `with_gallium_iris` / `with_intel_vk`). That chain is most of the work: LLVM+clang is 13 SBU and a 4.7 GB build tree per BLFS. Nothing hard-blocks. Two version facts matter: Wayfire 0.11.0 needs wlroots `>=0.20.0 <=0.20.99`, and BLFS ships wlroots 0.20.2, so they match. BLFS 13.1 already contains wlroots and Wayfire (pages `x/wlroots`, `x/wayfire`), so only iwd, wireless-regdb, foot, fcft, tllist and DejaVu come from upstream. Three BLFS "Required" dependencies are wrong for a Wayland-only system and are skipped (details in "Skipped"): Xorg Libraries for Mesa and xkeyboard-config, and nlohmann-json for Wayfire.

**Heaviest builds** (BLFS SBU, some include tests): LLVM+clang 13 · Mesa 3.4 · harfBuzz 0.9 · BlueZ 0.8 · glib 0.7 and PipeWire 0.7 (then Wayfire 0.6, SPIRV-Tools 0.6, SPIRV-LLVM-Translator 0.5).

Prefix: everything goes to `/usr`. BLFS's `$XORG_PREFIX` is `/usr` for us; do not create a separate X prefix.

## Rebuild order and cycle summary

```
libxml2 → libpng → FreeType(1) → GLib → HarfBuzz → FreeType(2) → Fontconfig → FriBidi → Pixman → Cairo → Pango
wayland → wayland-protocols; libdrm; libevdev+mtdev → libinput; xkeyboard-config → libxkbcommon
hwdata → libdisplay-info; libliftoff; lcms2; seatd(libseat)
Mako, PyYAML, SPIRV-Headers → SPIRV-Tools → glslang; LLVM+clang → SPIRV-LLVM-Translator → Mesa
yyjson, GLM, libjpeg-turbo → wlroots → Wayfire
tllist → fcft → foot            (after fontconfig, pixman, wayland, libxkbcommon)
alsa-lib → SBC → BlueZ → Lua → PipeWire → WirePlumber
iwd, wireless-regdb, OpenSSH, make-ca chain: independent of the rest
```

Only one true cycle: FreeType ↔ HarfBuzz, broken by building FreeType twice. Cairo ↔ HarfBuzz is a non-issue here because Cairo is built after HarfBuzz.

## Skipped on purpose

- **Xorg Libraries / libxcb / xcb-util / Xwayland / libpciaccess**: the target is Wayland-only. BLFS "Required: Xorg Libraries" on Mesa, xkeyboard-config and Vulkan-Loader do not hold for a Wayland-only build (Mesa and xkeyboard-config verified in source, Vulkan-Loader via its CMake option names). Consequence: no X11 apps at all (no Xwayland), so Electron or GTK apps that fall back to X11 will not start.
- **Linux-PAM**: no Phase 8a package *requires* it. It is only a question of how a user session is created (Open question 1).
- **curl, libarchive, libuv, libpsl, nghttp2**: nothing in the target closure needs them (make-ca 1.16.1 uses `openssl s_client`; CMake 4.4.2 is already built).
- **libical**: removed by BlueZ `--disable-obex` (OBEX file transfer); BLFS lists it as required.
- **nlohmann-json 3.12.0**: BLFS lists it as required for Wayfire, but `grep -rI nlohmann` over the 0.11.0 tarball (including bundled subprojects) finds nothing. If a later Wayfire needs it, it is a header-only CMake package.
- **gobject-introspection** (+ the glib two-pass): GNOME-only; GLib, Pango, WirePlumber built with introspection off.
- **ICU 78.3**: recommended for libxml2 and HarfBuzz; they run without it; it is large and Unicode-collation-only for our use.
- **Graphite2**: recommended for HarfBuzz; only TeX/LibreOffice use it.
- **docutils, libxslt, docbook, doxygen, Graphviz**: man-pages/docs only. BlueZ is the one place this bites (`--disable-manpages`).
- **shared-mime-info, desktop-file-utils**: GLib runtime niceties for GUI file handling; nothing in 8a is a GUI app.
- **gstreamer, PulseAudio, v4l-utils, FFmpeg, libcamera, JACK, fdk-aac, Opus, libusb** (PipeWire "recommended/optional"): not needed for audio output, Bluetooth A2DP (SBC) or the session manager. Add per feature later.
- **libva, libglvnd, libunwind, Valgrind, lm-sensors, mesa-demos, NASM**: Mesa/libjpeg optional extras. libva is VA-API hardware video decode, a later phase.
- **Rust, cbindgen, rust-bindgen**: only for Mesa's nouveau Vulkan and rusticl, neither built.
- **wlroots Vulkan renderer** (Vulkan-Loader + glslang at wlroots level): GLES2 renderer is the one Wayfire uses.
- **seatd daemon** (`-D server=enabled`): not built under the logind approach; changes if Open question 1 answers "no PAM".
- **libutf8proc / scdoc**: foot grapheme clustering and man pages. foot works without them (emoji ZWJ sequences render as separate glyphs).
- **wpa_supplicant, libnl, wireless_tools, iw**: iwd is the Wi-Fi stack; `iw` is a handy debug tool (BLFS `basicnet/iw`) but not required.
- **nss, GnuTLS, GnuPG**: make-ca's NSS DB output is optional; no 8a package reads it.

## Open questions for the main session

1. **PAM or not (the one that changes the package list).** libseat's logind backend, PipeWire/WirePlumber user units and `/run/user/$UID` all assume a *logind session*. On a tty login that session is created by `pam_systemd`, which means Linux-PAM + Shadow rebuilt with PAM + systemd rebuilt with PAM (BLFS notes all three). Without PAM, a logged-in user has no session, `libseat` fails with "no session", and `XDG_RUNTIME_DIR` is unset. Options: **(a) add PAM** (my recommendation: it is the BLFS-tested path, small packages, and sshd sessions then also get a runtime dir; cost is rebuilding Shadow and systemd); **(b) no PAM**: build seatd with `-D server=enabled -D libseat-seatd=enabled`, run `seatd.service`, put the user in a `seat` group, and `loginctl enable-linger <user>` so `user@UID.service` creates `/run/user/UID`; then export `XDG_RUNTIME_DIR` and `DBUS_SESSION_BUS_ADDRESS` yourself in the shell profile. (b) works but is hand-wired and untested by BLFS. What would change my mind: if hardening policy forbids PAM's extra attack surface, go (b).
2. **LLVM runtime dependency.** I could not tell without building whether `libgallium` links `libLLVM.so` for an iris+anv-only Mesa. If it does, LLVM+clang (1.1 GB installed) stays on the system forever; `-D shared-llvm=disabled` would static-link it instead (needs static libs, bigger build). Decide after the first Mesa build with `ldd`.
3. **Software GPU fallback for QEMU.** `scripts/qemu-boot.sh` boots the image in a VM, which has no Intel GPU. Adding `llvmpipe` to `gallium-drivers` and `swrast` to `vulkan-drivers` costs almost nothing once LLVM is built (and needs kernel `DRM_VGEM`), and lets Wayfire start in QEMU. Recommended: yes.
4. **NVIDIA dGPU left out.** Only the Intel iGPU is covered. If the laptop's NVIDIA GPU should ever drive a display, that needs a separate decision (nouveau/NVK needs Rust + cbindgen + bindgen, or the proprietary driver, which wlroots does not officially support). Not planned here.
5. **Fonts.** DejaVu 2.37 is a placeholder so text renders. BLFS prefers Noto (and Adwaita for GNOME-48+). Pick the real set (monospace for foot matters most) before Phase 8a ends; both are just files.
6. **Signature policy for U packages.** I recorded issuer key IDs only. Before trusting the six upstream tarballs, pin each key by an independent route (maintainer announcement, key in the project repo) and verify; Wayfire publishes a SHA-256 next to the tarball but no PGP signature, and DejaVu publishes none.
7. **Patches have no md5 on their BLFS pages** (libxkbcommon, LLVM, Lua). Fetch from https://www.linuxfromscratch.org/patches/blfs/13.1/ and record hashes when the files are staged.
8. **Kernel config deltas to fold into the next kernel build**: `DRM_I915`/`DRM_XE` (+ firmware), `INPUT_EVDEV`, `SND`+SOF/HDA, `BT*`/`RFKILL`/crypto set from the BlueZ page, the iwd crypto/keyring set in row #53, `CFG80211_REQUIRE_SIGNED_REGDB` consistent with the wireless-regdb key, `AUDIT` if PAM, `DRM_VGEM` if llvmpipe.

## What I did not verify

Nothing was compiled, so configure flags are derived from reading build files, not from a successful build. In particular: (a) Mesa `-D intel-rt` auto (ray tracing for `anv`) should be fine with the deps listed but is untested; (b) `LLVM_TARGETS_TO_BUILD="host"` is my narrowing of BLFS's `"host;AMDGPU"`, justified because AMDGPU modules are only requested for AMD drivers (Mesa `meson.build`), but untested; (c) libjpeg-turbo without NASM needing `-D WITH_SIMD=0` is from memory of its CMake behaviour; (d) signature validity.
