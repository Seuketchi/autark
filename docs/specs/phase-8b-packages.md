# Phase 8b — build list (shell toolchain: Rust, GTK4, polkit, UPower, sudo-rs, oo7)

Researched 2026-10-18. Research only: nothing was built or installed on this machine. "Verified" below means I read the fact in the package's own source (the release tarball or the tagged source) or computed a checksum, not that I compiled it. BLFS pages: <https://www.linuxfromscratch.org/blfs/view/stable-systemd/> (`stable-systemd` is 13.1, checked on the page's `<body id="blfs-13.1">`).

## Summary

**19 numbered packages**, all firm, plus 2 optional ones under Open question 2 (`setpriv`: libcap-ng and a util-linux rebuild). `autark-tools` itself is not a row; its system build deps are in "What the shell needs". Facts that change the list or the commands against the 2026-10-18 decision row:

- **Rust 1.97.1 builds on Autark's LLVM 22.1.8** (no bundled LLVM): rustc accepts LLVM 21 and newer with no upper bound, needs only LLVM's core components (so `LLVM_TARGETS_TO_BUILD="host"` is enough), and needs compiler-rt only for the profiler and sanitizers, which are off by default (`config.rs:1442` and `1494`). The chroot needs **no network** if the 3 stage0 files are staged first (list below); the crates come from the tarball's `vendor/`.
- **GTK 4.22.4 hard-requires libtiff** (its `meson.build` has `dependency('libtiff-4', 'tiff')` with no `required: false`). BLFS's GTK page does not list it, so tiff 4.7.2 is added as #3.
- **GTK 4.22.4 and adwaita-icon-theme 50.0 do not need librsvg** (verified: no meson dependency on it, GTK has its own SVG renderer `gtk/gtksvg.c` used by `gtk/gdktextureutils.c`). BLFS lists it as required anyway. Kept as decided; see Open question 3.
- **UPower 1.91.3 does not use libusb** (verified: no `libusb` anywhere in the tarball except `NEWS`), though BLFS lists it as required. libusb is skipped.
- **`setpriv` is not installed.** ch8's util-linux is configured `--disable-setpriv` and `autark-pkg` runs `setpriv` for every staged build (Open question 2). `wpctl`, `gio`, `kill`, `umount` are present.
- Switches that must be turned off or the build fails (all verified in the meson files): GTK `x11-backend` (default on), `media-gstreamer` (default **enabled**), `vulkan` (default enabled); gtk4-layer-shell `introspection` (default **true**); polkit `introspection` (default true). polkit also needs `-D os_type=lfs` and `-D pam_prefix=/etc/pam.d` or its PAM file is wrong or unread.
- A polkit authentication agent is **not** needed for `systemctl poweroff`/`reboot`/`suspend`/`hibernate` from the active local session: systemd 261.2's `org.freedesktop.login1.policy` has `allow_active=yes` for all four (also the `-multiple-sessions` variants). It is needed only when something holds a shutdown inhibitor (`*-ignore-inhibit` is `auth_admin_keep` for the active session). polkit itself **is** needed: without `polkitd` on the bus systemd treats the check as denied for non-root callers (`src/shared/bus-polkit.c`), and Autark's systemd already has the support compiled in (`ENABLE_POLKIT = feature.allowed()` in 261.2's `meson.build`, option left at auto), so no systemd rebuild.

**Heaviest builds** (BLFS SBU, without tests): rustc 10 (plus a 10 GB build tree and a RAM-hungry thin-LTO link; its tests are +15 SBU and are not planned) · cargo-c 0.7 · librsvg 0.6 · GTK 1.5 (BLFS figure includes docs; ours has none) · tiff 0.3 · polkit 0.3 · duktape 0.3 · gdk-pixbuf 0.2 · libepoxy 0.1; the rest under 0.1. About 14 SBU in total, nearly all of it Rust. gtk4-layer-shell, sudo-rs and oo7-daemon are not in BLFS, so they have no SBU figure (not measured).

**md5 check:** all 16 BLFS tarballs in the list, libusb (skipped) and the cargo-c `Cargo.lock` match the md5 printed on their BLFS page. No mismatch. For the 7 GNOME tarballs the publisher's `.sha256sum` (download.gnome.org) also matches what I computed.

Prefix: everything goes to `/usr`, Rust included (settled below).

## What I did not verify

Nothing was compiled, so every configure line is derived from reading build files. In particular: (a) **bindgen 0.69.5 and 0.72.1 with libclang 22.1.8** (pam-sys, libspa-sys, pipewire-sys): clang-sys 1.9.1 declares features only up to clang 20, so this pairing is untested; the existing build on this Ubuntu machine used a different libclang. (b) That 8a's LLVM `llvm-config --components` lists the core components and `x86` and that `llvm-config --link-shared` works: BLFS's build does, ours is narrower (`host` only, tests off) but I could not run it. (c) That curl-sys's fallback (compile the vendored curl and nghttp2 because the system libcurl has no HTTP/2) completes offline: I read the code path and confirmed the C sources are vendored, not built. (d) GitHub-generated archive hashes (gtk4-layer-shell, the sudo-rs and oo7 tags) could change if GitHub regenerates them. (e) No PGP signature was verified (the Rust `.asc` issuer key ID 85AB96E6FA1BE5FE was read from the packet only, not matched to a key). (f) polkit's `pam_prefix` and `os_type` behaviour is from reading `meson.build` and `data/meson.build`, not from an install. (g) The libcap-ng/util-linux `setpriv` route: configure flags and the `make setpriv` target are unchecked. (h) The installed system on the target was not inspected: "present" for `wpctl`, `gio`, `kill`, `umount` is from build options and sources. (i) SBU and disk figures are BLFS's, not measured here; Rust's RAM need is a judgement from the `lto = "thin"`, `codegen-units = 1` settings, not a measurement. (j) `autark-tools` effective features came from `cargo tree` on this machine's registry copy, which matches the lock (`--locked`) but was not built.
